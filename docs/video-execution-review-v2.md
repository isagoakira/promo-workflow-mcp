# Video execution and review v2

Promo owns storyboard, spoken script, recording/material instructions and acceptance intentions. Cutbench owns execution inside one production node: inspect inputs, construct tasks, produce a real preview, inspect, repair, recheck and return outputs or explicit planning gaps. There is no nine-stage prerequisite in the new bridge.

The stdio bridge sends `configure_execution` with `cut-production-v2` handoff fields and reads `execution.status`. A plan content hash covers locked master and requirements, not incoming material results. A plan change creates a separate deterministic project; old project files and approvals are untouched and never imported as a new pass. Material additions use `update_execution_assets` in the existing project. Registered preview IDs are namespaced by project in Promo, preventing collisions across plan versions.

Accepted material references are resolved through the immutable artifact store. Explicit `locator`, `localPath` or `filePath` fields at the root or inside `assets/files/entries/mediaSources/outputs/media/manifest` containers identify local files. Only absolute regular files are accepted. SHA-256 is computed from actual file bytes and checked against a declared hash when present; the artifact hash is separately preserved. IDs and provenance accompany each material. Prose and naked content strings are never interpreted as file paths. Missing manifests, locators, files or hash mismatches become explicit final-gate blockers instead of imaginary readable assets.

`WorkflowService.videoReview(workflowId)` returns immutable video metadata and annotation history. `videoAnnotate` requires workflow revision and idempotency key. Selections use milliseconds; start=end denotes a point; multiple ranges share one comment. Rectangles are normalized to the video image, excluding letterboxing. All annotations retain their original preview and hash identity; no automatic timestamp remapping is performed.

Agent receipts move open feedback to addressed; only the human workbench route can resolve or reopen. Resolution requires the current replacement preview, not the original video. Each feedback change invalidates cached final-gate results. Production lock calls the backend again, so stale cached acceptance cannot authorize a different video. The bridge imports human decisions and reads actual Cutbench repair receipts; it never manufactures an execution approval.

Existing stores without `videoReview` load an empty review state. Existing text-feedback fields and state transitions remain unchanged. Legacy stage records remain readable history. They cannot provide final videos or subtitles for the new gate. New subtitles must be registered execution deliverables bound to the current preview.

Human identity is trusted at the local authenticated review-host boundary; the service actor string is not an identity provider. Agent-facing MCP tools expose read and address operations, not human resolution. Preview media routes must serve only registered local files and verify the exact SHA-256 before playback. The current implementation does not claim an automatic video-understanding provider; actual checks must carry observed evidence and inspection provenance.
